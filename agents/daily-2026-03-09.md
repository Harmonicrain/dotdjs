## Issues Found

### 1. EventBus Listener Leak in `InteractionSystem.ts`
**Severity**: High (Memory/Behavior Leak)
**Description**: The `createInteractionSystem` factory function registers four `EventBus` listeners in its `init` method (`DOOR_OPEN_REQUEST`, `POWER_ON_REQUEST`, `WEAPON_PICKUP_REQUEST`, `PACK_A_PUNCH_REQUEST`). However, the returned interaction system object **does not provide a `dispose` method** to unregister them. According to `AGENTS.md` (Rule 7: Event & Timer Hygiene), all systems must clean up their listeners on disposal. When a map is restarted or the game is destroyed, these listeners will persist, causing multiple handlers to fire for a single event on subsequent playthroughs.

### 2. Strict Type Violation (`any`) in `ZoneSystem.ts`
**Severity**: Low (Technical Debt)
**Description**: `ZoneSystem.ts` casts `zone.bounds as any` on line 36 and line 61. `AGENTS.md` (Rule 13) mandates strict typing and forbidding `any`. Since `zone.bounds` is known to either be a standard `ZoneBounds` object (`minX`, `maxX`, etc.) or the tuple-based array from the schema (`min: number[], max: number[]`), it should be properly typed or type-narrowed instead of bypassing the compiler.
